Money Tracker PWA & LGTM Observability Stack

Technical reference covering the offline-first Progressive Web App, INR-first localization, FastAPI/SQLite ledger backend, Nginx gateway, and full 7-container OpenTelemetry observability stack.

1. Project Overview & Quick Start

Money Tracker is a personal expense and monthly budget tracker packaged as a self-contained docker compose stack. The user interface installs as a standalone PWA, queues mutations in IndexedDB when offline, and synchronizes idempotently with a FastAPI service backed by SQLite in WAL mode.

Currency formatting defaults to Indian Rupee (INR / ₹) using en-IN grouping on the client (with optional display switching to USD, EUR, or GBP in Settings) and CURRENCY=INR on the backend for API metadata and metric histogram units.

Single-Command Local Boot All seven services build and wire automatically over an isolated bridge network (money-tracker-net). Only HTTP gateway port 80 and Grafana port 3000 are published to the host.
zsh — Start entire stack & verify health 
docker compose up --build -d
docker compose ps
curl -fsS http://localhost:80/api/health
curl -fsS "http://localhost:80/api/dashboard?year=2026&month=11"

2. Frontend Tech Stack

The client emphasizes fast mobile ergonomics, zero third-party auth friction, reliable offline capture, and location-agnostic calendar date arithmetic.

Technology Version / Package Role in Application
React & Vite react@^18.3.1, vite@^6.1.0 Component rendering, reactive dashboard period navigation, fast hashed asset bundles.
Vite Plugin PWA vite-plugin-pwa@^0.21.1 Workbox service worker (sw.js) precaching JS/CSS/HTML/SVG/PNG/JSON assets with autoUpdate and API exclusion.
Tailwind CSS v4 tailwindcss@^4.0.9, @tailwindcss/vite Mobile-first utility styling, CSS custom properties, safe-area bottom nav, native <dialog> & <progress> theming.
Recharts & Lucide recharts@^2.15.1, lucide-react@^0.475.0 Responsive category donut chart, weekly/monthly spending trend line chart, crisp UI icons.
Temporal API Native + temporal-polyfill@^0.3.0 Conditional polyfill using Temporal.PlainDate & PlainYearMonth so YYYY-MM-DD dates never shift across UTC midnight.
IndexedDB & Intl money-tracker-pwa DB + Intl.NumberFormat Offline snapshots, mutation queue (pending_expenses, pending_budgets), and en-IN ₹ formatting via currency.js.

3. Backend Tech Stack

The API tier runs on Python 3.11 inside python:3.11-slim, exposing REST endpoints under /api with automatic Pydantic validation and SQLAlchemy ORM persistence.

FastAPI + Uvicorn

Typed REST API (/api/dashboard, /api/expenses, /api/budget, /api/health) with lifespan teardown flushing OTel providers cleanly.

SQLAlchemy 2 + SQLite WAL

Mapped models (User, Budget, Expense) storing calendar dates as indexed YYYY-MM-DD strings with foreign keys enabled.

OpenTelemetry SDK

Unified OTLP/HTTP exporter sending traces, custom metrics, and correlated structured logs directly to otel-collector:4318.

4. Observability & Infrastructure Stack

The monitoring plane implements the complete Grafana LGTM architecture decoupled through an OpenTelemetry Collector Contrib gateway.

Component Docker Image / Version Protocols & Storage
Nginx Proxy nginx:1.27-alpine Serves compiled Vite bundle on port 80, enforces PWA cache headers, proxies /api/* to backend.
OTel Collector otel/opentelemetry-collector-contrib:latest (v0.165+) Ingests OTLP gRPC (4317) & HTTP (4318); runs memory_limiter + batch processors; self-metrics on 8888.
Prometheus prom/prometheus:latest (v3) Receives metrics via prometheus_remote_write (--web.enable-remote-write-receiver) and scrapes collector/self metrics.
Loki grafana/loki:latest (v3) Native OTLP log ingestion (http://loki:3100/otlp) backed by TSDB + schema v13 structured metadata.
Tempo grafana/tempo:latest (v3) Monolithic trace storage (local blocks + WAL) accepting OTLP gRPC on port 4317, queried via HTTP 3200.
Grafana grafana/grafana:latest Pre-provisioned Prometheus, Loki, and Tempo datasources with Trace-to-Logs & Logs-to-Traces linking on port 3000.

Publishing on GitHub Pages

Every asset URL in docs/ uses relative paths (./assets/..., ./hld.html) and includes an empty docs/.nojekyll file, so the site works cleanly both at custom domains and under repository subpaths such as https://<username>.github.io/expense-tracker-PWA-LGTM-stack/.

  1. Push the repository (including the docs/ directory) to your main branch on GitHub.
  2. Open Repository Settings → Pages.
  3. Under Build and deployment → Source, choose Deploy from a branch.
  4. Select branch main and folder /docs, then click Save.
