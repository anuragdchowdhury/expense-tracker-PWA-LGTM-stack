Architecture Key

Two Logical Planes

Data Plane: Client PWA → Nginx → FastAPI → SQLite.

Telemetry Plane: FastAPI → OTel Collector → Prometheus / Loki / Tempo → Grafana.

High-Level Design (HLD)

End-to-end container topology, Docker network isolation, persistent volume boundaries, offline-first synchronization sequence, and Nginx reverse-proxy edge rules.

1. System Context & Container Topology

The platform separates user-facing ledger operations from telemetry fan-out so monitoring overhead never couples storage engines to application handlers. All inter-service resolution relies on Docker embedded DNS inside money-tracker-net.

2. Docker Bridge Network & Persistent Volumes

Only edge entrypoints bind to the host interface. Backend APIs, SQLite storage, Prometheus, Loki, Tempo, and the OTel Collector remain private to money-tracker-net.

Volume / Resource Container Mount Path Data Stored
backend-data /app/data (money-tracker-backend) SQLite database file (database.db), -wal, and -shm files.
prometheus-data /prometheus (money-tracker-prometheus) Time-series TSDB blocks pushed via prometheus_remote_write and scrape targets.
loki-data /loki (money-tracker-loki) Log chunks, TSDB v13 index, retention compactor working files.
tempo-data /var/tempo (money-tracker-tempo) Trace WAL and monolithic local Parquet/trace blocks.
grafana-data /var/lib/grafana (money-tracker-grafana) Grafana internal SQLite database and session/user settings (provisioning mounted read-only).

3. Offline-First PWA & Idempotent Sync Flow

Expenses can be captured seamlessly even with airplane mode enabled. Every client-created expense generates a deterministic UUID (client_id) via crypto.randomUUID(). When connectivity resumes, syncPendingChanges() replays queued budgets first, then pending expenses. Because expenses.client_id carries a UNIQUE constraint in SQLite, duplicate retries return the existing row idempotently instead of double-counting spending.

4. Nginx Reverse Proxy & PWA Caching Strategy

Correct HTTP cache headers are essential for Progressive Web Apps: a cached sw.js or stale index.html can trap clients on an outdated build. Nginx enforces strict differentiation between mutable entrypoints and content-hashed bundles:

Location Match Directive / Policy Architectural Rationale
= /index.html Cache-Control: no-cache, no-store, must-revalidate Ensures browsers always resolve the latest hashed JS/CSS bundle URLs.
sw.js, manifest.json, workbox-*.js Cache-Control: no-cache, no-store, must-revalidate Lets Workbox registerType: 'autoUpdate' detect new service worker revisions immediately.
/assets/ Cache-Control: public, max-age=31536000, immutable Vite injects content hashes into asset filenames; long-lived immutable caching maximizes speed.
/api/ proxy_pass http://backend:8000; Same-origin reverse proxy eliminates browser CORS preflight latency and hides internal Python port.
/ (fallback) try_files $uri $uri/ /index.html; Enables client-side routing without Nginx 404 responses on deep reloads.
