Observability & LGTM Stack Setup

Unified telemetry architecture emitting correlated traces, custom business metrics, and structured logs from FastAPI and SQLite3 through the OpenTelemetry Collector into Loki, Grafana, Tempo, and Prometheus.

1. Telemetry Signals Pipeline (Traces, Metrics, Logs)

All three telemetry pillars leave money-tracker-backend over OTLP/HTTP (port 4318) toward otel-collector, decoupled from downstream storage protocols so collector batching, memory protection, and routing stay centrally managed.

2. FastAPI & SQLite3 OpenTelemetry Instrumentation

setup_observability() in backend/main.py initializes three OpenTelemetry SDK providers tagged with resource attributes service.name=money-tracker-backend, service.version=1.0.0, and service.namespace=money-tracker. Unit tests toggle OTEL_DISABLE_EXPORTERS=true so spans execute in-memory without network calls.

Automatic Instrumentors

FastAPIInstrumentor creates HTTP server root spans; SQLite3Instrumentor emits child database query spans; LoggingInstrumentor plus TraceContextFilter inject trace_id and span_id onto every log record.

Custom Counters

money_tracker_expenses_created (labeled by category), money_tracker_budget_updated, and money_tracker_dashboard_requests export every 5 seconds via PeriodicExportingMetricReader.

Currency Histogram

money_tracker_expense_amount records recorded expense sizes by category using unit=DEFAULT_CURRENCY (defaulting to INR via CURRENCY=INR).

3. OpenTelemetry Collector Contrib Configuration

Configured in observability/otel-collector-config.yaml for Collector Contrib v0.165+. Notice three production details critical on modern images:

  • Exporter names use modern protocol-specific keys: prometheus_remote_write, otlp_http/loki, and otlp_grpc/tempo.
  • resource_to_telemetry_conversion: enabled: true promotes service.name and resource metadata into queryable Prometheus labels.
  • service.telemetry.metrics.readers configures the pull Prometheus self-metrics endpoint on 0.0.0.0:8888 (replacing removed legacy address field).
yaml — observability/otel-collector-config.yaml (pipelines) 
exporters:
  prometheus_remote_write:
    endpoint: "http://prometheus:9090/api/v1/write"
    resource_to_telemetry_conversion:
      enabled: true
    tls:
      insecure: true

  otlp_http/loki:
    endpoint: "http://loki:3100/otlp"
    tls:
      insecure: true

  otlp_grpc/tempo:
    endpoint: "tempo:4317"
    tls:
      insecure: true

service:
  pipelines:
    traces:  { receivers: [otlp], processors: [memory_limiter, batch], exporters: [otlp_grpc/tempo] }
    metrics: { receivers: [otlp], processors: [memory_limiter, batch], exporters: [prometheus_remote_write] }
    logs:    { receivers: [otlp], processors: [memory_limiter, batch], exporters: [otlp_http/loki] }

4. Prometheus v3, Loki v3, and Tempo v3 Setup

Backend Version Nuances & Key Settings
Prometheus v3 (observability/prometheus.yaml) Started with --web.enable-remote-write-receiver and --web.enable-otlp-receiver. Scrapes localhost:9090 and otel-collector:8888 every 15s.
Loki v3 (observability/loki-config.yaml) Ingests native OTLP logs at /otlp. Requires schema: v13 with store: tsdb when allow_structured_metadata: true, promoting service.name, service.namespace, and deployment.environment to index labels.
Tempo v3 (observability/tempo.yaml) Uses simplified monolithic config (omits removed Tempo v2 ingester: and compactor: blocks). Receives OTLP on :4317/:4318 and writes WAL + blocks under /var/tempo.

5. Grafana Datasources & Trace-to-Logs Correlation

Provisioning files under observability/grafana/provisioning/ configure Prometheus (UID prometheus, default datasource), Loki (loki), and Tempo (tempo) plus the auto-loaded dashboard Money Tracker - LGTM Observability (uid: money-tracker-lgtm).

Bi-Directional Investigation Workflow In Loki, derivedFields match both structured metadata label trace_id and inline text trace_id=([0-9a-fA-F]+) to jump straight into Tempo spans. In Tempo, tracesToLogsV2 maps service.name to service_name so clicking any FastAPI or SQLite span opens its correlated log lines in Loki automatically.
